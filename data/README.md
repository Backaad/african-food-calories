# Data

The repository holds **no images**. It holds the list of sources, their licences
and credits, and the scripts that fetch the images from where they are published.

| File | What it is |
|---|---|
| [`sources.yaml`](sources.yaml) | Every image source considered, its licence, authors to credit, and whether we use it (and why not). |
| [`dishes.yaml`](dishes.yaml) | The dish catalogue, with the Commons categories and Openverse queries used to find images. |
| [`inventory.py`](inventory.py) | Counts openly licensed images per dish (metadata only) and writes `inventory/inventory.md` and `inventory/counts.json`. |
| [`download.py`](download.py) | Downloads the images into `raw/<dish>/` with `raw/ATTRIBUTION.csv` (author, licence, link for every file). |
| [`inventory/`](inventory/) | Latest inventory table, generated by the script. |

## Licence rules

- Kept: CC0, public domain, CC BY, CC BY-SA (any version), checked **per image**.
- Dropped: NonCommercial, NoDerivatives, unknown or missing licences, GFDL-only.
- Never used, whatever licence a dataset declares: images taken from Google,
  Facebook, Instagram, YouTube or Bing. A dataset author cannot relicense photos
  they do not own.
- The scripts refuse any source whose status in `sources.yaml` is not
  `approved` or `approved_per_item`.

## Run it

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r data/requirements-dev.txt
python -m pytest -q data/tests

python data/inventory.py                    # counts only, no image download
python data/download.py --only ndole        # images + credits for one dish
python data/download.py --dry-run           # credits only, no download
```

Openverse limits anonymous API use. To raise the limit, register an Openverse API
application and export `OPENVERSE_CLIENT_ID` and `OPENVERSE_CLIENT_SECRET`
(in CI, as repository secrets). Never commit them.

The `data` GitHub Actions workflow runs the tests and the inventory on every pull
request that touches `data/`; the table appears in the run summary and as the
`data-inventory` artifact.

## What the counts mean

Counts are **candidates**, not usable photos. Before training, each image still
needs a check: is it the right dish, a real photo, not a duplicate? Openverse
counts are keyword matches and much noisier than Commons categories, so the
inventory reports them separately as an upper bound.

## Crediting images

Anyone who redistributes downloaded images must ship `ATTRIBUTION.csv` with
them. CC BY and CC BY-SA require naming the author and the licence; CC BY-SA
also requires sharing adapted images under the same licence.
